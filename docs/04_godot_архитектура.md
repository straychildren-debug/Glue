# Архитектура Godot

Это проектная схема, а не уже существующий код. Версию Godot, размеры спрайтов и конкретные узлы физического соединения надо выбрать при запуске прототипа.

```text
Game
├─ Level (выбранная сцена)
│  ├─ Ground: TileMapLayer
│  ├─ Decoration: TileMapLayer / Sprite2D
│  ├─ Background: слои параллакса
│  ├─ Objects: экземпляры интерактивных сцен
│  ├─ SpawnPoints
│  ├─ Checkpoints
│  └─ Finish
├─ Players: 2–4 экземпляра Player
├─ CameraController: общая камера
└─ LevelManager: загрузка, финиш, респавн, чекпоинты
```

`Player.tscn`: корень `CharacterBody2D`, `CollisionShape2D`, `AnimatedSprite2D`, зона доступного хвата, контроллер сцепки и контроллер платформенного режима. В раннем описании `Player` и `CharacterBody2D` стояли разными строками; для реальной сцены удобно сделать `CharacterBody2D` корнем. Все четыре цвета используют одну сцену с параметром материала/палитры.

## Системы

| Система | Ответственность |
|---|---|
| InputRouter | подключение игроков по кнопке, привязка геймпада (device id) к игроку и цвету, клавиатура для отладки, отключение/переподключение устройства |
| PlayerController | ввод своего устройства, бег, прыжок, запрет/разрешение действий по состоянию |
| GrabController | выбор цели, создание/снятие связи, передача движения и веса, ослабление хвата |
| PlatformController | фиксация, твёрдая опора, наклон, оживление, взаимодействие с грузом |
| CameraController | общая область игроков, плавный масштаб, предельное отдаление, переходы зон |
| LevelManager | состав команды, спавн, чекпоинты, условие «все на финише», перезапуск |
| MechanismController | вес, кнопки, фиксированные состояния, реакции дверей и платформ |

Переиспользуемые сцены: `Crate.tscn`, `Button.tscn`, `Door.tscn`, `MovingPlatform.tscn`, `Rope.tscn`, `Seesaw.tscn`, `Checkpoint.tscn`, `Finish.tscn`. Для мира также понадобятся мостовая секция, крепление, грузовой подъёмник и опасность, если их нельзя выразить перечисленными сценами. Уровень собирается из TileSet и этих экземпляров, без отдельного скрипта для каждой загадки.

**В прототипе (этап 3)** механизмы лежат в `src/mechanisms/` как скрипты, которые кладутся прямо в сцену уровня:
- `Weight` — общий расчёт опор и нагрузки за кадр;
- `Crate` — ящик;
- `PressurePlate` — плита или защёлка;
- `Door` — заслонка: дверь или выдвижной мост;
- `Seesaw` — качели-весы с броском и фиксатором (`lock`);
- `DoorKey` и `KeyLock` — ключ и замок (замок — триггер заслонки, как плита);
- `Hook` — крюк: для хвата это вечный замерший якорь (`grab_target` — товарищ или крюк);
- `Lift` — подъёмник: две площадки на тросе, перевешивает разница весов.

**Этап 5 (01.10.2026):** главная сцена — меню `src/menu/level_select.tscn`. Каталог миров и уровней — `src/game/levels.gd` (`Levels`): в каждом мире 20 записей, пустая сцена означает «ещё не собран». Прогресс — `src/game/progress.gd` (`Progress`, файл `user://progress.cfg`). `Game.play(tree, world, index)` запускает уровень из каталога; `Game.open_menu(tree)` возвращает в меню. Пауза — `src/menu/pause_menu.gd`, ввод в меню с любого устройства — `src/menu/menu_input.gd`. Новый уровень добавляется так: сцена в `levels/` из `GreyboxLevel` и механизмов, путь — в `Levels.WORLDS`, сценарий прохождения парой — в автотест.

Механизмы из группы `resettable` отдают `save_state()`/`load_state()`. `GreyboxLevel` снимает их состояние при взятии чекпоинта и восстанавливает при общем респавне. Замерший на механизме едет вместе с ним: механизмы из группы `carriers` после своего движения вызывают `Player.follow_carrier()`.

## Контракты систем

- Один и тот же файл уровня загружается для 2/3/4 игроков. Доступны параметры механизмов, зависящие от `player_count`; геометрию под состав команды не переключать по умолчанию.
- Связи между игроками удаляются безопасно при отпускании хвата, смерти, чекпоинте и смене уровня. Один игрок не должен физически затянуть остальных в недоступную область после респавна.
- Финиш требует присутствия всех активных игроков. Вышедший из игры участник не должен оставаться обязательным условием финиша.
- Замерший игрок остаётся управляемым в разрешённых пределах: наклон и снятие фиксации. Нельзя создавать долгую роль «стоять на кнопке и ждать».
- Механизмы, которые открывают односторонний путь, должны иметь возвратный рычаг, стопор, обход или безопасный чекпоинт, чтобы второй игрок мог пройти.

## Сборка и проверка

Сначала прототип на цветных прямоугольниках с двумя игроками. Добавить отладочное отображение коллизий, зон хвата, активных связей, нагрузки механизмов и текущего чекпоинта. После проверки пары подключить третьего и четвёртого игрока без изменения основной сцены. Визуальные PNG заменить после стабилизации физики.
